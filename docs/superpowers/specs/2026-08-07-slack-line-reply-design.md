# Slack返信作成→LINE自動送信（③最終形） 設計書

- 作成日: 2026-08-07
- ステータス: 承認済み（実装へ）
- 前提: 知識ループ（2026-08-07-nakano-knowledge-loop-design.md）と
  LINE紐付け（2026-08-07-line-account-linking-design.md）が本番稼働済み

## 1. 目的

エスカレされた質問への担当回答を、**Slackの入力ボックスから直接、本人のLINEへ送信**する。
これまで「Slackで相談 → 公式LINEを開いて手で返信」だった往復をなくす。
あわせて、その回答を中野くんの知識に入れるかを**毎回チェックボックスで選べる**ようにする。

## 2. フロー

```
エスカレ通知（Slack・既存）
  → ボタン「✍️ 返信を作成」（旧「📚 知識の文案を作る」を改名・拡張）
  → 入力ボックス（モーダル・既存を拡張）:
      質問表示 / 回答入力欄 /
      ☑ LINEで本人に送信（連携済みのときだけ表示・既定ON）
      ☑ 中野くんの知識に追加（承認待ちへ）（既定ON）
  → 送信:
      ① LINEチェックあり → 公式LINEからプッシュ送信（課金対象）
      ② 知識チェックあり → 承認待ちドラフト作成（既存経路・AI整形なし）
      ③ スレッドに記録「📤 ○○さん宛にLINEで送信しました（回答者: X）＋回答本文」
  → LINE送信失敗（未連携化・ブロック・通数上限等）は
      モーダルにエラーを返して何も保存しない（担当がすぐ気付いて再試行/手動対応できる）
```

- メンバーが**LINE未連携**の場合: LINE送信のチェックボックス自体を出さず、
  「⚠️ この方はLINE未連携のため、送信は手動でお願いします」の注意書きを表示。
  知識追加だけは可能（従来のモーダルと同等）
- 両方チェックなしで送信 → エラー「送信先か知識追加のどちらかを選んでください」

## 3. LINEプッシュ送信

- `lib/line-bot.ts` に `linePushText(lineUserId, text)` を追加
  （POST /v2/bot/message/push。**リトライしない** — プッシュは冪等でなく、
  タイムアウト誤判定での二重送信はメンバー体験を直接損ねる。失敗は担当に返して人が判断）
- 送信文面: `ご質問いただいた件、担当より回答します😊\n\n${回答}`
  （公式LINEの既存トーンに合わせる。質問の引用は付けない — 本人は自分の質問を覚えており、
  長文化はプッシュ課金・可読性の両面で損）
- **課金**: フリープラン=月200通。超過するとLINE APIがエラーを返す → モーダルにエラー表示
  → スレッドにも残らないので、担当は手動LINEに切替え。月間通数はLINE公式アカウント管理画面で確認
  （アプリ内カウンタは作らない。エスカレ件数は管理画面「担当に回した数」で近似できるため）
- `getLineLinkByUserId` が `is_active` を見ないのは意図どおり: 「質問した本人に返す」文脈では、
  退職済みでも紐付けが残っていれば回答を届けたい（送信可否をactiveで絞る理由が無い）

## 4. モーダルの変更（app/api/webhooks/slack-interactive）

- block_actions: escalation逆引き後、**質問者の連携状態を取得**
  （`lib/line-link-data.ts` に `getLineLinkByUserId(userId): {lineUserId, name} | null` を追加）し、
  モーダルのblocksを出し分け:
  - 連携済み: checkboxes要素（`send_line` 既定ON / `save_knowledge` 既定ON）
  - 未連携: contextブロックで注意書き＋checkboxes（`save_knowledge` のみ・既定ON）
- private_metadata に `{channel, ts}`（既存のまま。連携状態は view_submission 時に**取り直す**
  — モーダルを開いたまま放置され状態が変わるケースに備え、送信時点の真実で判定）
- view_submission:
  1. 回答テキスト・チェック状態を取得。両方OFFならerrors
  2. `send_line` ON → 連携再確認 → `linePushText`。失敗なら errors（何も保存しない）
  3. `save_knowledge` ON → 既存の承認待ちドラフト作成（重複チェック含む既存ロジック）
  4. スレッド記録（LINE送信の有無・宛先名・回答者・本文）
  5. response_action: clear
- 処理順は **LINE送信 → ドラフト → スレッド記録**（一番失敗しやすく取り返しがつかないものを先頭に。
  ドラフト以降の失敗はwarnで許容 — LINEは既に届いており、やり直すと二重送信になるため）

## 5. 文言・表示

- エスカレ通知のボタン: 「✍️ 返信を作成」（機能が知識化専用でなくなったため改名）
- 通知末尾のヒント行も「ボタンから返信を書くと、LINE送信と知識化ができます（📚リアクションでも知識化のみ可能）」の趣旨に更新
- 📚リアクション経路（スレッド返信→AI整形→承認待ち）は**そのまま残す**（LINE送信はしない）

## 6. エラー処理

| 事象 | 挙動 |
|---|---|
| LINE push失敗（上限・ブロック・トークン不備） | モーダルにerrors表示・何も保存しない。理由はconsole.warn |
| 送信後のドラフト作成失敗 | warn（LINEは届いている。スレッド記録に「知識追加は失敗」を添える） |
| スレッド記録失敗 | warn（本体処理は成立） |
| 未連携なのにsend_lineが来た（改竄・状態変化） | 送信時の再確認で弾いてerrors |
| 押し直し・担当2人の同時操作 | `nakano_escalations.line_replied_at` のclaimで二重送信防止（後勝ちは弾かれerrors、push失敗時はclaimを戻して再試行可） |

## 7. スコープ外（今回はやらない）

- 月間通数のアプリ内カウンタ（LINE管理画面で足りる。超過が常態化したらプラン変更かカウンタ追加を判断）
- 一斉送信・リマインド送信（個別回答のみ）
- 既読管理・返信の取り込み（メンバーの返信は従来どおり手動チャット＋中野くんへ誘導）

## 改訂メモ（2026-08-07 レビュー対応）

- LINE送信の冪等ガードを追加: `nakano_escalations` に `line_replied_at` を追加
  （`supabase-migration-nakano-escalations-line-replied.sql`）し、push直前に
  `claimLineReply`/`releaseLineReply`（`lib/nakano-loop-data.ts`）で送信権をclaimする。
  押し直し・担当2人の同時操作による二重LINE送信を防ぐ
- モーダルに送信先名を表示（連携済み時、質問の下にcontextブロックで「送信先: ○○さん（LINE連携済み）」）
- 重複ドラフト検出時は「失敗」ではなく「既に登録済み」の文言に変更（実エラーと区別）
- 両方OFFエラーの表示先を `answer_block` から `options_block` に変更（チェックボックスの下に出るように）
- `getLineLinkByUserId` の例外時（未連携との区別）はモーダルを開かず、スレッドに再試行を促す案内をbest-effortで投稿
- デプロイ前に開かれていた旧モーダル（`options_block` 無し）からの送信は、従来どおり知識化のみとして処理
- `linePushText` の fetch に2.5sタイムアウトを追加（view_submissionの3秒制限内に失敗を返すため）
- 氏名未設定時の表記を「本人さん」ではなく「本人」に修正
