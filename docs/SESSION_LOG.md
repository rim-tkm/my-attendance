## 2026-08-07（その3）中野くん知識ループの実装（Slackスレッド回答→📚→承認→知識化）

### 何を作ったか
Slackで担当が中野くんのエスカレスレッドに回答し、その返信に**📚リアクション**を付けると、AIが質問と回答から知識文案（タイトル＋本文）を自動生成。管理画面の承認待ち一覧に出て、**承認して初めて本番知識（`nakano_knowledge`）に入る**（却下も可）。これで「Slackで答えた内容」が中野くんの回答精度に還元されるループができた。

主要ファイル:
- `lib/slack-bot.ts` — Slack Bot APIクライアント（投稿ts取得・署名検証・スレッド取得・permalink取得）
- `lib/nakano-loop-data.ts` — エスカレ対応表・承認待ちドラフトのデータ層（作成・承認・却下）
- `lib/nakano-draft.ts` — 質問＋Slack回答から知識文案をAIで整形（JSON抽出・切り詰め検知込み）
- `app/api/webhooks/slack-events/route.ts` — Slackイベント受信（署名検証・`reaction_added`受信・📚で文案生成）
- `app/api/admin/nakano/drafts/route.ts` / `[id]/route.ts` — 承認待ち一覧・承認（編集込み）・却下API
- `AdminNakanoSection` の DraftsCard（`app/components/AdminNakanoSection.tsx`）— 管理画面の承認待ちUI
- `supabase-migration-nakano-knowledge-loop.sql` — テーブル `nakano_escalations` / `nakano_knowledge_drafts`

### 設計書・計画書
- `docs/superpowers/specs/2026-08-07-nakano-knowledge-loop-design.md`
- `docs/superpowers/plans/2026-08-07-nakano-knowledge-loop.md`

### レビューで直した主な欠陥
- **二重承認の知識重複レース**: 同一ドラフトを2人がほぼ同時に承認すると知識が2件できる可能性 → 承認処理をステータス確保先行に変更（コミット `2871b48`）
- **Bot失敗時の通知消失**: Bot投稿が失敗すると担当への通知自体が消えていた → Webhookへのフォールバックを追加（コミット `756cbc0`）
- **知識化失敗の無音化**: 📚を付けても文案生成が失敗すると何も起きず気づけない → エラー診断情報を追加しJSON抽出を頑健化（コミット `6f6dcd8`）
- **`maxDuration`未設定＋SDK既定timeout10分の組み合わせ**: Vercel Functionsのデフォルト実行時間を超えて処理が中断されうる → `app/api/webhooks/slack-events/route.ts` に `export const maxDuration = 60` を設定
- **承認後の再📚重複**: 承認済みのエスカレに再度📚を押すと重複ドラフトができる可能性 → 重複チェックを強化（コミット `3daf50a`）
- **rejectの無音成功**: 却下ボタンでエラーが起きても画面に反映されず一覧が古いまま → エラー後に承認待ち一覧を取り直すよう修正（コミット `16ec873`）

### 実行済みSQL
- テーブル2つ（`nakano_escalations` / `nakano_knowledge_drafts`）は**本番実行済み**。
- **部分ユニークインデックス `uniq_nakano_drafts_pending_escalation`（同一エスカレへのpendingドラフトを1件に制限）は、ユーザーが実行したか未確認。** 次に触る人は先に確認すること。未実行なら `supabase-migration-nakano-knowledge-loop.sql` の該当CREATE INDEX文をSupabase SQL Editorで実行する。

## 2026-08-07（その2）FAQ導線の強化＋エスカレーション取りこぼしの修正

### ① よくある質問ボタンの利用0件 → 導線を強化（コミット 45c3aa6）
- 原因は内容ではなく**導線**。パネルを開くと空の会話エリア(flex-1)が縦を食い、FAQが入力欄の上に押し下げられて気づかれない。送信すると `setStepsOpen(false)` で畳まれ二度と出ない
- 対策: **会話が空のときだけ、会話エリアの先頭にFAQボタンをカードで大きく提示**。重複を避けフッター版は会話開始後のみ表示（[NakanoBotWidget.tsx](../app/components/NakanoBotWidget.tsx)）
- FAQツリーは正常（ルート9カテゴリ、内容も業務頻出に合致）。集計も正しい。純粋にUX問題だった

### ②【重要】担当への通知が飛ばない → エスカレーション取りこぼしを修正（コミット ac88372）
**症状**: 中野くんが「担当に確認して折り返しますね。」と返したのにSlack通知が来ない。

**確定した原因**（DB実データで証明）: エスカレーションの唯一のトリガーは `escalate_to_admin`
**ツール呼び出し**。ところがモデルが気まぐれにツールを呼ばず、その一文だけを"ただのテキスト"
として書くことがある。同一文言「担当に確認して折り返しますね。」で `escalated=true`（ツール呼んだ）
と `escalated=false`（呼ばなかった＝通知なし）が混在していた。8/6テストで動いていたのは、
たまたま毎回ツールを呼べていただけ。`effort:low` ＋ プロンプトの「一文だけ書いて」指示が
"文を書けば済む"という誤解を誘発していた。

**対策（防御の多層化。コードが主役・プロンプトは補助）**:
- **安全網**: `lib/nakano.ts` の `looksLikeNakanoDeferral()` を追加。ツール未発火でも本文が
  「担当に確認/折り返します」や「手元の資料になく/推測でお答えできません」を示していれば、
  `app/api/nakano/chat` で拾って**必ず担当へエスカレーション**（Slack通知＋ラベル＋escalated保存）
- **プロンプト補強**: 「担当に回すなら必ずツールを呼ぶ／文章だけでは届かない／定型文はシステムが
  添えるので本文は書かなくてよい」と明確化（[nakano-prompt.ts](../lib/nakano-prompt.ts)）
- 誤通知（オオカミ少年化）を避けるため、個人実績の画面案内は拾わない。判定を実例9件で確認（9/9）

**地雷として記憶**: 中野くんのエスカレーションは「モデルがツールを呼ぶ」ことに依存する。
プロンプトやモデル(effort含む)を変えると呼ぶ頻度が揺れる。安全網があるので致命傷は防げるが、
`looksLikeNakanoDeferral` の網羅性は、新しい断り文句が出たら都度広げること。

### 申し送り（この日その2ぶん）
- 反映後、実際に「答えられない質問」を1つ投げて **`ai-中野くん-溢れた質問` に通知が来るか**を確認したい（安全網の実挙動確認）
- 余力があれば **モードA（配送）の潜在リスク**も点検: `SLACK_WEBHOOK_NAKANO_URL` 未設定だと
  デフォルトSlackにフォールバックする（[slack-webhook.ts](../lib/slack-webhook.ts)）。重要通知が黙って別チャンネルに
  行きうるので、未設定時は警告する等の改善余地あり（今回は証拠が無いので未着手）

### 費用まわり（この日の主題）
**きっかけ**: 入力1,667・出力854トークンなのに概算83円と表示され、数字と金額が噛み合わなかった。
**原因**: 費用の大半は**キャッシュの読み書き**なのに、それを画面に出していなかった。

- 知識67項目（約2万文字）を毎回送っているので、**キャッシュが効くかどうかで1問の単価が10倍以上変わる**
  - キャッシュ書き込み（初回）≒19円/問 ／ 読み出し（2回目以降）≒1.5円/問
  - テスト時は1人が散発的に聞くだけなので、ほぼ毎回いちばん高い値段になる。**この数字で判断してはいけない**
- 300件/日でキャッシュが効けば**月1万円前後**の見込み

**新しい仕組み**
- `lib/nakano-cost.ts` に単価と計算を集約（画面とCronで二重に持つとモデル切替時にズレるため）
- `app/api/cron/nakano-cost-alert` — 毎日21時（JST）、**1日の費用がしきい値超えの日だけ**Slack通知。既定1,000円、`NAKANO_DAILY_YEN_ALERT` で変更可
- 通知文が**判断の分かれ目まで書く**: キャッシュ80%未満なら「件数が少ないだけ、様子見」／80%以上なら「モデルを下げる検討時期」
  - これを分けないと、たまたま質問が少なかった日にモデルを下げてしまう
